# 카카오 로컬 API 데이터 저장 정리 계획

> 상태: **계획 (미착수)** — 2026-11-11 작성. 공공 주소 API 키 발급을 기다리는 중.

## 왜

카카오 데브톡 공식 답변(2026-10-19, 답변자 "Map"):

- "좌표와 주소 정보를 저장하여 활용하는 형태는 허용하지 않습니다." / "실시간 호출로만 이용 가능합니다."
- "장소ID, URL은 저장하여 카카오맵으로 랜딩하는 구조로 활용할 수 있습니다."
- 후속 답변(10-20): 장소 ID·URL만 저장하고 **주소·좌표는 공공기관 API로 따로 확보**해 저장하는 방식은 "가능합니다".

출처: https://devtalk.kakao.com/t/api-id/152228 — 정식 약관 조항이 아닌 포럼 답변이지만,
운영정책 제5조 20호(목적 외 캐시 금지)·30호(데이터 복제·제공 금지)와 같은 취지라 Play 정식 출시 전에 정리한다.

## 지금 저장하는 것 (위반 소지)

식당 등록(위저드·방 화면 검색·추천의 위시리스트 담기)에서 카카오 장소 검색 결과의
`place_name`, `address_name`, `x`, `y`를 `RoomRestaurant.name/address/province/city/neighborhood/latitude/longitude`에 그대로 저장한다.
좌표를 쓰는 곳: 방 지도·지역 탭·근처 위시리스트 배너(room.astro), 식당 상세 지도(restaurant.astro),
"오늘 뭐 먹지?" 방향·거리 계산(lib/recommend*.ts), 공개 방 페이지.

## 목표 구조

| 필드 | 출처 | 비고 |
| --- | --- | --- |
| `kakaoPlaceId`, `placeUrl` (신규) | 카카오 | 저장 허용. "카카오맵에서 보기" 링크 |
| `name` | 사용자 확인 | 등록 화면에서 사용자가 확인·수정한 값(사용자 입력)으로 취급 |
| `address`, `province/city/neighborhood` | **도로명주소 API(행정안전부)** | 카카오 주소 대신 공공 API로 정규화한 주소 저장 |
| `latitude`, `longitude` | **공공 지오코더** (도로명주소 좌표 API 또는 VWorld) | 카카오 좌표 대신 저장 |
| 전화번호·영업시간 등 | 카카오 실시간 | 저장하지 않고 화면에서 그때그때 조회 (지금도 저장 안 함) |

## 단계

1. **키 발급 (사람 작업)** — 아래 중 하나
   - 도로명주소 API 검색 + 좌표제공 API: https://business.juso.go.kr (개발용 키 즉시 발급, 운영 키 승인)
   - VWorld 지오코더: https://www.vworld.kr (무료, 일 4만 건)
2. API에 `/geo/resolve` 추가: 카카오 장소 → 공공 API로 주소·좌표 조회 (키는 서버 환경변수, 프런트 노출 금지)
3. 스키마: `RoomRestaurant.placeUrl` 추가 (`kakaoPlaceId`는 Post 쪽에 이미 있음 — RoomRestaurant에도 추가). 둘 다 nullable이라 `db push`로 데이터 손실 없음
4. 등록 경로 3곳이 카카오 주소·좌표 대신 2의 결과를 저장하도록 변경
5. **기존 데이터 이관**: 운영 204곳의 주소 문자열을 공공 API로 다시 조회해 주소·좌표를 덮어쓴다
   (1회성 스크립트, 실패 건은 좌표 null로 두고 목록에 남김). 실행 전 백업
6. 공개 방 페이지(현재 숨김)도 같은 데이터만 쓰는지 확인

## 남는 위험

- 공공 API 좌표는 건물 입구 기준이라 카카오 좌표와 수십 m 차이가 날 수 있다 (지도 표시엔 충분)
- 상가 내 매장처럼 주소가 같은 식당은 좌표가 겹친다
- 포럼 답변은 바뀔 수 있다 → 정식 출시 전 카카오 제휴 문의로 한 번 더 확인 권장
