# 제품 방향 (2026-08 전환)

이 문서는 "왜 지금 이 작업을 하고, 왜 저 작업은 안 하는지"의 기준이다.
새 기능을 만들기 전에 여기부터 읽는다.

## 1. 전환 요약

| | 이전 | 지금 |
| --- | --- | --- |
| 정체성 | 광고·협찬 없는 **맛집 리뷰 플랫폼** | 친구·연인이 반복해서 쓰는 **프라이빗 그룹 도구** |
| 성장 채널 | SEO (공개 방·허브·가이드) | **초대 바이럴** (기존 유저의 카톡방) |
| 공개 방 | 성장의 핵심 장치 | 부가 기능 (진입점 숨김) |
| 핵심 지표 | MAU | **활성 방 수 · 2번째 기록 도달률** |

### 왜 바꿨나

1. **프라이버시 약속과 SEO 전략이 정면 충돌한다.** "우리끼리만 보는 비공개 방"이
   핵심 가치인데 성장 전략은 "방을 공개해서 검색 노출"이었다. 공개 방 0개는
   기능 홍보 부족이 아니라 **유인이 없는 구조**의 결과다.
2. **UGC 맛집 콘텐츠로 검색 상위는 불가능하다.** 네이버 블로그·플레이스,
   카카오맵, 다이닝코드가 장악한 SERP에 리뷰 몇 개짜리 페이지로 못 들어간다.
3. **한국 맛집 검색은 구글에서 거의 안 일어난다.** 반면 "맛집 기록 앱",
   "커플 맛집 리스트" 같은 **도구 탐색형 검색**은 구글 비중이 크다.

## 2. 유지 / 동결 목록

### 계속 키운다
- `/guide/*` (how-to 8종), `/use/*` (유즈케이스 4종) — 도구 탐색 검색의 착지점
- 초대 퍼널 (방 생성 → 카톡 공유 → 첫 기록)
- 공유 투표 (`/vote/:token`) — 가입 없이 참여 가능한 유일한 진입점

### 3개월 동결 (기능은 살아 있고 진입점만 숨김)
`apps/web/src/lib/features.ts` 플래그로 제어한다.

| 대상 | 플래그 | 되살릴 기준 |
| --- | --- | --- |
| 공개 방 목록 | `SHOW_PUBLIC_ROOMS` | 품질 필터 통과 공개 방 5개 이상 |
| 커뮤니티 | `SHOW_COMMUNITY` | 최근 30일 게시글 20개 이상 |
| 랭킹 | `SHOW_RANKINGS` | 랭킹 표본 유저 50명 이상 |

동결 이유: 콘텐츠가 없는 화면을 신규 유저에게 보여주면 신뢰가 깎인다.
(공개 방 목록 "아직 공개된 방이 없어요", 맛집 추천 1위가 리뷰 1개짜리 ★5 식당)

### 하지 않는다
- 공개 맛집 SEO 확장 (지역/카테고리 허브 추가 생성)
- 광고 게재 — "광고 없는 솔직한 후기"와 정면 충돌하고 이 규모에선 수익도 안 난다
- 식당 제휴·데이터 판매 — 프라이빗 서비스의 신뢰를 깬다
- BM 설계 전반 — 활성 방이 먼저다

## 3. 판정 기준 (3개월)

> **방 30개를 만들고, 그중 10개가 한 달 뒤에도 쓰는가.**

- 10개 이상 → 계속 키운다
- 그 이하 → 제품 문제다. 마케팅으로 덮지 말고 방향 전환 또는 정리

## 4. 계측 (GA4)

퍼널 이벤트는 `apps/web/src/lib/api.ts`의 API 호출 지점에 붙어 있다.
페이지가 늘어나도 이벤트가 새지 않게 하기 위함이다.

| 이벤트 | 주요 파라미터 | 보는 것 |
| --- | --- | --- |
| `room_created` | max_members, poll_enabled | 방 생성 수 |
| `invite_shared` | method (copy_link/kakao) | 초대 전송률 |
| `room_joined` | method (invite_code/public) | **초대 수락률** |
| `restaurant_added` | is_wishlist, has_category | 첫 기록 도달 |
| `visit_created`, `review_created` | rating, has_content, has_detail_rating | 기록 완주 · 세부 평점 실사용률 |
| `room_opened` | member_count, restaurant_count, **is_solo** | **활성 방 · 2번째 식당 도달 · 혼자 남은 방** |
| `poll_created`, `poll_voted`, `poll_shared` | method | 투표 훅 작동 여부 |
| `shared_poll_viewed`, `shared_poll_voted` | token | **비로그인 참여 전환** |

가장 먼저 볼 것: `room_opened`의 `is_solo` 비율과 `restaurant_count` 분포.

## 5. 공유 투표 (콜드 스타트 우회)

```
방장(로그인) → 투표 생성 → 카톡 공유
   → 친구(비로그인) → /vote/:token → 클릭 한 번으로 투표
   → 결과 화면 CTA → "먹고 나서 후기도 남겨보세요" → 가입
```

- **생성은 로그인 유지.** 공개 생성(`/poll/new`)까지 열지 않은 이유는 그 페이지로
  들어올 유입이 지금 없기 때문이다. 실현 가능한 유통 경로는 기존 유저의 카톡방뿐.
  유입이 생기면 그때 연다 (스키마는 그대로 두고 엔드포인트만 추가하면 된다).
- **공개 범위**: 투표 제목·선택지·득표수만. 방 이름·멤버·식당·리뷰는 응답에 없다. `noindex`.
- **중복 방지**: 브라우저 랜덤 토큰만. IP 차단·핑거프린팅은 쓰지 않는다
  (회사·카페 공유 IP 오탐이 실익보다 크다).
- **만료**: 14일 (`RoomsService.POLL_SHARE_TTL_DAYS`).

## 6. 디자인 부채 (인지하고 미뤄둔 것)

- 브랜드 컬러 없음 (`--accent: #333`, 전면 그레이스케일). 화면의 유일한 색이
  카카오 노랑·네이버 초록이라 남의 브랜드 색이 우리 색처럼 보인다.
- 이모지 아이콘(🍽️📋👥)은 OS마다 다르게 렌더된다.
- 활성화 퍼널이 먼저라 미뤘다. 식당 카드 썸네일만 우선 반영했다.
